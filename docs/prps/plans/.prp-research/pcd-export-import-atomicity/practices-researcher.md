# Practices Research: PCD Export/Import Atomicity (YAN-463, YAN-466)

Approach fixed in `docs/plans/pcd-export-import-atomicity/feature-spec.md`: exporter tags batch ops with `export_batch: true`; `markBaseOrphaned` excludes them via `json_extract`; `importBaseOps` failure rollback widened to all `pcd_ops` rows + id watermarks, applied in one synchronous native transaction (no `db.transaction`, no awaits). This document is only the pattern-mirror cheat sheet for the plan.

## NOT Building

- **No `db.transaction()` wrapper** around the import: async `BEGIN … await … COMMIT` on the shared singleton captures unrelated concurrent writes (spec decision D3; warnings already documented in `db/queries/driftStatus.ts:128-131`); rollback runs as one synchronous native transaction instead.
- **No savepoints** per candidate: first failure aborts the whole import, so nested savepoints add machinery for zero behavior change.
- **No new `source` enum value** (`'export'` etc.): CHECK constraint on `pcd_ops.source` blocks it; metadata flag is the discriminator (spec D1).
- **No YAML regeneration on export** in this PR: canonical `entities/*.yaml` publish is the deferred follow-up (spec D2); don't drag `converter.ts`/`serialize.ts` into the fix.
- **No shared exporter/importer "sync" abstraction**: timestamped SQL audit dumps vs curated YAML entities is a false symmetry; keep two local fixes.
- **No backfill migration** for legacy un-flagged batch rows: documented behavior, follow-up repair (spec edge case 2).
- **No DI framework / interface extraction** for `pcdOpsQueries`: object-literal patching is the established seam; adding an interface would churn every existing test.
- **No new test alias plumbing** unless one line in `scripts/test.ts` — don't build a test-discovery system.
- **No snapshot of the cache**: in-memory cache recovery stays the existing `invalidate(databaseId)` call; only `pcd_ops`/`pcd_op_history` rows are snapshotted.
- **No per-PCD mutex / locking layer**: existing job serialization covers it; flagged as follow-up (spec Risks).
- **No schema migration at all**: `metadata` JSON flag + watermark math reuse existing columns.
