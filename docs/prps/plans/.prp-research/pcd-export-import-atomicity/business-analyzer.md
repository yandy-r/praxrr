## User Story

| Story                                                                                                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| As a PCD maintainer/operator, I want exported drafts to survive every later import and a failed import to leave `pcd_ops` and `pcd_op_history` exactly as before, so that publishing never silently reverts and the base layer is never a hybrid of old and new repo state. |

## Problem → Solution

| Current                                                                                                                                                                                                                                                          | Desired                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| YAN-463: `exportDraftOps` inserts a published `source='repo'` batch op (`ops/<n>.sql`); import reads only `entities/` YAML, never refreshes its `last_seen_in_repo_at`, so `markBaseOrphaned` orphans it and the exported change reverts.                        | Batch op metadata carries `export_batch: true`; `markBaseOrphaned` skips rows with that flag (`json_extract(metadata,'$.export_batch') IS NULL`). Export → import leaves batch op `published`, change present in cache. All other repo ops still orphan on upstream removal.                                                                                                     |
| YAN-466: failed import restores only refreshed repo-base rows (#275); rows created in the pass stay as orphans (with history), `updated_at` not restored, user ops mutated by compile auto-override are outside the snapshot, retry can hit filename collisions. | Snapshot ALL `pcd_ops` rows of the database + id watermarks (ops, history) before writes. On any failure (candidate write, orphan sweep, final compile) run one synchronous native transaction: delete `pcd_op_history` > watermark, delete `pcd_ops` > watermark, restore every snapshot row column-for-column (incl. `updated_at`); then `invalidate(databaseId)` and rethrow. |
| Legacy export batch rows lack the flag.                                                                                                                                                                                                                          | Unflagged rows keep orphaning (no backfill); behavior documented; repair is a follow-up.                                                                                                                                                                                                                                                                                         |
| YAML regen on export, `filePaths` confinement, per-PCD mutex, YAN-465.                                                                                                                                                                                           | Out of scope (follow-up issues). No schema/API/UI change; `Base op import failed:` messages unchanged.                                                                                                                                                                                                                                                                           |

## Acceptance Criteria

| #   | Criterion (testable)                                                                                                                                                                                                                       | Type        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------- |
| 1   | - [ ] `exportDraftOps` batch op `metadata` JSON parses with `export_batch === true`; draft ops are still superseded and history rows written as before.                                                                                    | Unit        |
| 2   | - [ ] Export then `importBaseOps` (YAML reader stubbed to unrelated entities): batch op `state` stays `published`, `orphaned` count excludes it, exported change resolves in compiled cache.                                               | Round-trip  |
| 3   | - [ ] Same import still orphans a normal `source='repo'` base op absent upstream (exclusion is flag-only, not all-batch).                                                                                                                  | Regression  |
| 4   | - [ ] Legacy edge: a `published` `source='repo'` row with batch-shaped metadata (`operation:'export'`) but NO `export_batch` is still orphaned on import; no backfill occurs.                                                              | Edge        |
| 5   | - [ ] Rows with null/invalid-JSON `metadata` do not break the sweep (still orphaned if stale, no SQL error).                                                                                                                               | Edge        |
| 6   | - [ ] Forced failure mid-import after row A rewritten and row B inserted: `pcd_ops` for the database is identical to pre-import for every column incl. `updated_at`; B is gone (not orphaned); B's `pcd_op_history` rows are gone.         | Failure     |
| 7   | - [ ] Failure at each stage (candidate deserialize error, `markBaseOrphaned` throw, final `compile` throw) restores identically; `pcd_op_history` row set equals pre-import.                                                               | Failure     |
| 8   | - [ ] Restore also reverts `source`, `state`, `filename`, `superseded_by_op_id`, `pushed_*` of base ops of any source/state and all user ops (not only `source='repo'` base).                                                              | Failure     |
| 9   | - [ ] User-op restore: final `compile` runs auto-override resolution that mutates/supersedes user ops and then throws → user ops return to snapshot values; no user op left changed.                                                       | Edge        |
| 10  | - [ ] Restore executes as one synchronous transaction (no `await` inside); history deleted before ops (no FK violation); rollback of the transaction itself on restore error leaves DB unchanged and original import error still surfaces. | Integrity   |
| 11  | - [ ] Rows with ids ≤ watermark that existed pre-import (including rows of other databases) are never deleted or modified; only this database's rows are touched.                                                                          | Isolation   |
| 12  | - [ ] Retry after failure: second `importBaseOps` on fixed input succeeds with no unique `filename` collision and converges to same state as a clean first import.                                                                         | Retry       |
| 13  | - [ ] Retry after failure with the same failing input fails again and again restores to the identical pre-import state (idempotent failure).                                                                                               | Retry       |
| 14  | - [ ] Registered cache is invalidated on failure; next read rebuilds and matches restored rows (no stale swapped cache).                                                                                                                   | Failure     |
| 15  | - [ ] Failure with zero candidates (orphan-only path) and failure before any write still leaves state unchanged and does not delete pre-existing rows.                                                                                     | Edge        |
| 16  | - [ ] `pcdManager.sync`/`switchBranch`/`link` still surface `Base op import failed: <reason>`; `sync` returns `success:false` and does not trigger Arr sync fanout or update `synced_at`.                                                  | Integration |
| 17  | - [ ] Successful import leaves no snapshot side effects (no extra rows, history, or log noise beyond debug exclusion count).                                                                                                               | Regression  |
| 18  | - [ ] Existing `importBaseOps.test.ts` (incl. #275/#286 cases), `deno task test`, and `deno task check` pass; no schema migration or OpenAPI change.                                                                                       | Gate        |
