# business-analyzer: shared-sanitized-markdown (YAN-560 / GH #289)

Paths are relative to `packages/praxrr-app/src/` unless noted. Builds on `docs/plans/shared-sanitized-markdown/feature-spec.md` and `research-business.md`. Line numbers were checked against the worktree on 2026-10-07.

## User Story

| Role            | Want                                                                                      | So that                                                                                       | Source                              |
| --------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------- |
| Praxrr operator | Browse and sync third-party PCDs and TRaSH data                                           | A malicious description cannot run script in an authenticated session that holds Arr API keys | feature-spec.md "User Stories"      |
| Praxrr operator | Descriptions keep rendering bold, italic, code, links, lists and tables exactly as before | No visual regression from a security refactor                                                 | feature-spec.md "User Stories"      |
| PCD author      | The `MarkdownInput` preview matches the final rendered output                             | What they preview is what readers see                                                         | feature-spec.md "User Stories"      |
| PCD maintainer  | Before/after markdown diffs on the changes page render safely                             | Reviewing upstream changes cannot trigger XSS                                                 | research-business.md "User Stories" |

## Problem → Solution

| #   | Problem (evidence)                                                                                                                                                                                                                                                 | Solution (from spec)                                                                                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Seven client files import `marked` directly and send its output to `{@html}` or to a Table `{ html }` cell with no sanitization. Examples: `lib/client/ui/display/Markdown.svelte:2,18` and `routes/databases/[id]/changes/components/TestsDiffTable.svelte:4,112` | Add one isomorphic module `lib/shared/markdown/markdown.ts` exporting `parseMarkdown`, `parseMarkdownInline` and `sanitizeHtml`. Every sink imports from it. |
| 2   | The server sanitizer is regex-based and can be bypassed: unquoted `onerror=`, unquoted or entity-encoded `javascript:`, and `data:` (`lib/server/utils/markdown/markdown.ts:53-54,76-84`)                                                                          | Replace it with `xss@1.0.15` (`FilterXSS`), an explicit tag/attribute allowlist and a URL scheme policy.                                                     |
| 3   | Server importers depend on `$utils/markdown/markdown.ts`: `trashguide/displayTransform.ts:20`, `pcd/entities/qualityProfiles/list.ts:16`, `routes/databases/[id]/config/+page.server.ts:13`                                                                        | Turn the server file into a re-export shim. The three importers need no edits.                                                                               |
| 4   | Nothing stops a new raw `{@html}`: `svelte/no-at-html-tags` is not enabled in `eslint.config.js`, which only uses `svelte.configs.base`                                                                                                                            | Enable the rule as `'error'`. Each remaining legitimate sink gets a narrow, justified `eslint-disable-next-line`.                                            |
| 5   | Inline sites (cards, table cells inside a `<span>` or `<div>`) and block sites (diffs, preview) use different parse modes                                                                                                                                          | Keep each site's current mode: `parseMarkdownInline` for inline sites, `parseMarkdown` for block sites (table below).                                        |
| 6   | Stored data could be altered by mistake                                                                                                                                                                                                                            | Sanitize at render time only. No migrations, no changes to PCD ops or the app DB.                                                                            |

Summary: inline sites are `Markdown.svelte` (default and all three users), CF CardView, CF TableView and regex TableView. Block sites are MarkdownInput, FieldDiffTable, TestsDiffTable and the server `parseMarkdown`.

Note: TRaSH pages pass server-rendered block HTML into inline `<Markdown>`. Today it is re-parsed with `parseInline`, and raw HTML passes through. The sanitizer must be idempotent on that input (spec edge case "Already-sanitized HTML re-sanitized").

## Gaps

- GAP: no automated Svelte component render tests exist, so render-parity criteria #19–22 are checked by inspection, unit tests on the functions and a manual smoke test.
- GAP: no existing `no-restricted-imports` rule for `marked`. Criterion #1 is enforced by grep, not lint.
- Not covered by these criteria: Table cell producers that interpolate raw values (metadata-profiles `row.description` / `row.name`, delay-profiles `row.name`). The spec escapes the confirmed ones; they are not markdown sinks.
